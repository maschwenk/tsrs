# Rust practices

`docs/PORTING.md` says how Go becomes Rust. This file says what the Rust must not do, how that is checked, and which
performance techniques are in place, rejected or untried.

The port keeps the shape of the Go code, so clippy's style advice does not apply. What a port gets wrong is cost that
Go hides or does not have: copies, allocations, argument passing, hash iteration order, and `unsafe`. The rules below
target those. They come from reading how other Rust projects with this workload keep their code fast and sound (as of
2026-10): Bun (also an agent-written port, Zig to Rust), oxc, Rolldown, rust-analyzer, Ruff and ty, Biome, Turborepo
and swc. Where a rule copies one of them, it says which.

## The lint ratchet

```sh
tools/lint/ratchet.py        # must pass before a change lands; CI runs it as the `lint-ratchet` job
```

`[workspace.lints.clippy]` in `Cargo.toml` and `clippy.toml` turn on a chosen set of clippy lints. The code that
existed when they were turned on has findings; `tools/lint/baseline.tsv` records them as one count per lint and file.
The ratchet runs clippy and fails when a (lint, file) count is above its baseline. So existing findings are not
errors, and nobody fixes them in passing (PORTING.md: no cleanups mixed into other work), but a change cannot add one.
The mechanism is Bun's (`mordant-baseline.toml`: "A PR fails only when it adds one").

When it fails, it prints the new findings, on the lines the branch changed when git can tell.

- Fix the finding. `cargo +<toolchain> clippy -p <crate>` shows clippy's suggestion.
- If the flagged code is intended, put `#[expect(clippy::<lint>, reason = "...")]` on the smallest item or statement
  that covers it. The reason is for the next reader; for `inline_always` and the unchecked operations it cites the
  measurement. Use `#[expect]`, not `#[allow]`: it warns once the lint stops firing, so a suppression cannot outlive
  its cause. A bare `#[allow]` is itself a finding.
- Do not raise `baseline.tsv`.

Paying findings down is separate work: `tools/lint/ratchet.py --list clippy::redundant_clone`, fix one lint or one
crate, run the usual test gates, then `tools/lint/ratchet.py --update`. `--update` only lowers counts, and it lists
the rows it left alone because another OS may still have the findings: a file that this OS does not compile is
lowered by `--update` on the OS that does, a file with platform `cfg`s only by hand.

Details:

- Findings depend on the clippy version, so the ratchet runs the toolchain `rust-toolchain.toml` pins, everywhere.
  A Rust upgrade re-baselines it ("Upgrading Rust" below).
- It covers the library and binary targets of every workspace crate except the generated `tsrs_fourslash`, and
  skips files that start with `// Code generated by ...; DO NOT EDIT.` (their findings belong to the generator).
- `unsafe_op_in_unsafe_fn`, `dead_code`, `unused_imports`, `unused_variables` and `unused_mut` are rustc lints that
  the ratchet adds on the command line: `cargo check` runs with `-D warnings`, so they cannot be warnings in
  `[workspace.lints.rust]` (where the last four stay `allow`) while findings remain.
- `tools/lint/ratchet.py --self-test` checks the comparison logic without running cargo.

## Upgrading Rust

`rust-toolchain.toml` pins one Rust version for local builds, CI, clippy, the bench and releases; every workflow
installs that version. Floating stable would change the compiler under the bench every six weeks, and the regression
flag would blame whichever pull request merged next. An upgrade is a pull request of its own:

1. Change `channel` in `rust-toolchain.toml`.
2. Fix what the new compiler rejects (`cargo check` runs with `-D warnings`).
3. Re-baseline the lint ratchet: `python3 tools/lint/ratchet.py --update --allow-increase` on macOS and on Linux. From
   a Mac, the Linux half is
   `docker run --rm -v "$PWD":/w -w /w -e CARGO_TARGET_DIR=/tmp/t rust:<version> bash -c 'rustup component add clippy && python3 tools/lint/ratchet.py --update --allow-increase'`.
4. After the merge, the bench run on main prints the instruction and peak-memory change per project as the upgrade's
   measurement (`bench/regressions.py` sees the rustc change and flags nothing). Put it in the pull request.
5. Release builds use the same version; run the `Release` workflow by hand (`dry_run` on) to check them.

## Source checks

`tools/lint/source.py` (CI: the `lint-ratchet` job) checks two things clippy cannot express:

- **`unsafe impl Send` / `Sync`.** `tools/lint/send_sync.tsv` lists all of them (29 on 2026-10-05). Adding or removing
  one fails until `tools/lint/source.py --update` records it, so every new cross-thread escape is a reviewed line in a
  diff. `P<T>` is `Send + Sync` by decree (PORTING.md, "Threading"), so the compiler does not police these. After Bun's
  `vm-thread-door` inventory.
- **Weakened atomic orderings.** A `Relaxed`, `Acquire`, `Release` or `AcqRel` needs a `//` comment on its line or in
  the three lines above saying why the ordering is enough (Bun: "default to seq_cst and comment any weakened
  ordering"). `tools/lint/atomics.tsv` counts the ones without a comment per file (81 in 25 files); a file may not
  go above its count.

Test files, the generated fourslash crate and generated files are not scanned.

## What the lints check

`awk -F'\t' '!/^#/{n[$2]+=$1} END{for (l in n) print n[l], l}' tools/lint/baseline.tsv | sort -rn` prints the current
count per lint.

| Group | Lints | Why |
| --- | --- | --- |
| Bugs | clippy's `correctness` and `suspicious` groups | Almost always real mistakes (`never_loop`, `mut_from_ref`, `uninit_vec`). rust-analyzer denies `correctness`. |
| Performance | clippy's `perf` group | Known slower forms: two hash lookups where `entry` does one, `Box<Vec<T>>`, a large `Err` type. rust-analyzer denies `perf`. |
| Clones | `redundant_clone`, `clone_on_copy`, `implicit_clone`, `clone_on_ref_ptr`, `assigning_clones`, `cloned_instead_of_copied` | Go copies pointers; a port turns many of those into `.clone()`. With these on, a `.clone()` that remains is a real copy, and a reference-count bump reads `Arc::clone(&x)`, which matters on the paths the checker threads share. Bun, oxc, Rolldown, Ruff, Biome. |
| Allocations | `format_push_string`, `inefficient_to_string`, `needless_collect`, `unnecessary_box_returns`, `rc_buffer`, `vec_box`, `stable_sort_primitive` | A temporary `String`, `Vec` or `Box` that the code did not need. Bun, oxc, Biome. |
| Arguments and stack | `needless_pass_by_value`, `trivially_copy_pass_by_ref`, `large_types_passed_by_value`, `large_stack_arrays`, `large_stack_frames`, `inline_always` | The signature table in PORTING.md, checked: `&str` and `&[T]` in, small `Copy` values by value. `#[inline(always)]` needs a measurement, as in oxc, where each one carries `#[expect(clippy::inline_always)]` and a comment. Bun, Biome. |
| Hashing | `disallowed_types` (`std::collections::HashMap` / `HashSet`), `set_contains_or_insert`, `zero_sized_map_values`, `iter_over_hash_type` | PORTING.md already requires `FxHashMap`; std's maps use SipHash. `iter_over_hash_type` flags iterating a hash map or set: the order must never reach a diagnostic or emitted text (sort, or use `OrderedMap`). oxc, Rolldown, rust-analyzer, Bun ban the std maps; Ruff uses `iter_over_hash_type`. |
| Locks and threads | `mutex_atomic`, `mutex_integer`, `rc_mutex`, `significant_drop_in_scrutinee`, `non_send_fields_in_send_ty` | A mutex around a flag or counter, a lock guard held across a whole `match`, and every new `unsafe impl Send` over non-`Send` fields (the "by decree" impls in PORTING.md "Threading") becomes a reviewed line. |
| `unsafe` | `undocumented_unsafe_blocks`, `missing_safety_doc`, `unsafe_op_in_unsafe_fn`, `ptr_as_ptr`, `ptr_cast_constness`, `ref_as_ptr`, `borrow_as_ptr`, `cast_ptr_alignment`, `as_ptr_cast_mut`, `transmute_ptr_to_ptr`, `mem_forget`, `disallowed_methods` | Every `unsafe` block states its invariant in a `// SAFETY:` comment. Pointer casts use the forms that cannot change mutability or type by accident. `clippy.toml` lists the unchecked operations (`get_unchecked`, `unwrap_unchecked`, `unreachable_unchecked`, `from_utf8_unchecked`): each needs a reason that cites a measurement. Bun, oxc, rust-analyzer. |
| Leftovers | `dbg_macro`, `todo`, `unimplemented`, `disallowed_macros`, `allow_attributes`, `allow_attributes_without_reason` | Debugging output and placeholders do not land; suppressions are `#[expect]` with a reason. Bun, oxc and Rolldown have all of the first three; rust-analyzer, Ruff and Biome have `dbg_macro`. |
| Unused code | `dead_code`, `unused_imports`, `unused_variables`, `unused_mut` (rustc) | Allowed workspace-wide while porting; ratcheted since 2026-10-05 so new unused code does not land (Bun denies `dead_code`). Unused imports and `mut` were removed with `cargo fix`. Unused variables are not prefixed with `_` in bulk: in a port an unused parameter can mean the Rust code dropped something the Go code uses, so each is checked against Go. |

Left off on purpose: the `style`, `complexity` and `pedantic` groups (they would rewrite Go-shaped code), `unwrap_used`
(Go's nil dereference is a panic too), `or_fun_call` (it turns `unwrap_or(f())` into `unwrap_or_else(f)`; Go evaluates
`f` eagerly, and when `f` creates a type or symbol, skipping it changes ids and so output order; oxc and Rolldown
leave it off too), the cast lints (the port has about 1,000 `as usize`), `print_stdout` /
`print_stderr` (the CLI and the `TSRS_*` diagnostics print).

## Rules that only review checks

1. **A performance claim comes with numbers.** Instructions retired and peak RSS, before and after, same machine,
   one checker and the default: `/usr/bin/time -l` on macOS, `perf stat` on Linux. Wall time on a shared machine is
   noise. Write the result in `notes/`. (Bun: "Performance claims need numbers ... must not regress ANY measured case".)
2. **Build settings are measurements, not defaults.** `[profile.dist]` (fat LTO, one codegen unit, PGO:
   `notes/perf-pgo.md`), mimalloc, transparent huge pages for the arena on Linux (`notes/linux-perf.md`,
   `notes/linux-x86-round.md`), 32-bit handles (`notes/mem-pointer-compression.md`). Change one only with a
   measurement. (Bun: "Never change optimization levels,
   LTO modes, or tuning knobs assuming higher is better — existing settings encode prior measurements.")
3. **Arena struct sizes are pinned.** A type with one instance per node, symbol, type, signature or link has
   `const _: () = assert!(std::mem::size_of::<T>() == N);` next to it. A change that edits `N` states the old and new
   size and the census result (`notes/mem-census.md`). (oxc generates these for every AST type; ty pins `Type` at 16
   bytes; rust-analyzer pins `TypeRef`.)
4. **Return what is stored; allocate once.** Where Go returns a stored slice or string, Rust returns `&'static [T]`
   or `&'static str`, not a fresh `Vec` or `String` (`notes/cpu-checker.md` changes 6 to 8 found such copies by profiling:
   304.9 G -> 296.3 G instructions; `notes/fix-perf-memory.md` found per-call copies of names and lists). When a hot path changes, check it with
   `--features alloc-profile`. In a recursive collector, pass an accumulator instead of returning a collection per
   level (rust-analyzer style guide, "Premature Pessimization").
5. **Comparators are total orders.** Rust's `sort_by` may panic on a comparator that is not one; Go's does not.
   Where the Go comparator is not total, complete it with a tie-breaker (`notes/lsp-memfix.md`).
6. **Slow paths are split out.** The rare branch of a hot function goes into a `#[cold]` function so the common
   path does not pay for the rare one (`notes/perf-parse.md` changes 6 to 8; oxc builds parser diagnostics in a `#[cold]`
   function).
7. **A complexity claim is checked by doubling the input.** "Linear now" or "no longer quadratic" comes with the
   measurement at N and 2N and the ratio (Bun: "Verify complexity claims by doubling inputs and reporting the ratio").
8. **Preconditions are assertions, not prose.** A helper's documented precondition becomes a `debug_assert!` at its
   head (an `assert!` when breaking it would corrupt memory); a comment cannot fail (Bun: "Encode documented
   preconditions as debug assertions rather than prose").

## Techniques

In place:

| Technique | Evidence here | Also in |
| --- | --- | --- |
| Fat LTO, one codegen unit, PGO for release binaries | `notes/perf-pgo.md`: -13.5% instructions with PGO; fat LTO alone about -2% | oxc, Rolldown, swc (fat); Ruff (fat, PGO); Turborepo, rust-analyzer (thin) |
| BOLT on top of PGO for the Linux release binaries (`.github/scripts/bolt.sh`, gates run on the BOLT-optimized binaries) | `notes/perf-build-level.md`: -2.7% / -3.2% / -1.0% wall at 1 / 4 / 8 checkers on the 38k-file codebase, -3.4 to -4.0% on vscode; instruction-cache misses -20% | rustc and Python (CPython) release builds, Chromium, Meta services |
| mimalloc as the global allocator | `notes/fix-perf-memory.md` | oxc, Rolldown, Turborepo, Bun |

| Instruction counts and peak memory per merge, flagged on regression | `bench/README.md` "Regression flag": single-threaded tsrs repeats to about 0.001% (instructions) and under 0.4% (peak RSS); a project up more than 1% (and 2 MiB for memory) gets a comment on the PR | CodSpeed in oxc, Rolldown, Ruff, Biome, swc (simulated counts); Ruff's PR memory report |

| Frame pointers for profiling | `docs/DEBUGGING.md` "Profiling": a `dist` build with `-C force-frame-pointers=yes` for samply / `perf` on Linux (Apple arm64 always keeps them) | Bun |
| Transparent huge pages for the arena on Linux: large thread-arena chunks 2 MiB-aligned and advised with `MADV_HUGEPAGE` | `notes/linux-x86-round.md`: 2-6% less wall time, 21-48x fewer page faults; `notes/linux-perf.md`: THP off costs 11-12% | mimalloc (advises its own OS memory) |

Measured and rejected (do not retry without new evidence): explicit huge pages on top of mimalloc's, pre-faulting and
mmap'd arena chunks without advice (`notes/linux-perf.md`; the compressed arena's reservation is not mimalloc memory and
needs the advice: `notes/linux-x86-round.md`); global identifier interning (`notes/mem-round2.md`: parse +9% time); rolling back whole
regions of speculative work (`notes/mem-overload-rollback.md`); bump regions per inference scope
(`notes/mem-scoped-arenas.md`: 25 to 50% of scopes keep something reachable). Restructuring generic
callbacks to cut monomorphization (`notes/monomorphization-audit.md`: closures are 3.6% of the checker's LLVM IR, the
largest tsrs generic `filter_type` 1.1%, on a hot path). A target CPU above the x86-64 baseline
(`notes/linux-x86-round.md`: `x86-64-v3` takes 1-2% more cycles, `v2` changes nothing). PGO hot/cold text grouping
(`-z keep-text-section-prefix`; `notes/perf-probes-2026-10-05.md`: about 0.5% more cycles on every project).
Identifiers that carry their hash (same note: all Fx hashing is 0.7-1.4% of instructions, not worth a hash field on
every name).

Not pursued: a binary-size check (Bun fails a pull request that grows the binary by more than 0.5 MB); size is not a
goal here (owner decision, 2026-10-05).

Does not transfer: nightly-only flags (Bun's `-Zbuild-std`, `-Zlocation-detail=none`, `-Zshare-generics`; the release
toolchain is stable), lifetime-carrying arenas such as bumpalo's `&'a T` (PORTING.md: no lifetime parameters), oxc's
compile-time ban on `Drop` types in the arena (arena objects here own `Vec`s and maps on purpose), thin LTO (fat LTO
already covers it).
