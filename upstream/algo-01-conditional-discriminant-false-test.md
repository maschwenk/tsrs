decide a distributive conditional's definitely-false test from one discriminant property

`Extract<U, { kind: K }>`, `Exclude<...>` and hand-written `T extends { type: K } ? ... : never` evaluate one constituent at a time. for a union of N object types and M discriminant values that is N x M calls to `getConditionalType`, and almost all of them go through `isTypeAssignableTo(getPermissiveInstantiation(checkType), getPermissiveInstantiation(extendsType))` only to find out that the constituent's `kind` is a different literal. in practice most of these don't come from the distribution loop in `getConditionalTypeInstantiation`: a mapped type over the keys (`{ [K in Kind]: Extract<Ev, { kind: K }> }`) resolves the template once with `K` generic, which distributes into a union of N deferred conditional types, and each key then instantiates that union constituent by constituent (one `getConditionalTypeInstantiation` miss and one failing relation each)

the relation fails in `propertiesRelatedTo` at the first property whose comparison fails, and when both property types are non-structured (literals, enum literals, unique symbols, primitives, null, undefined, never) that comparison is `s == t || isSimpleTypeRelatedTo(s, t)`. so for an object (or intersection) check type and a non-generic object extends type that isn't a reference to a generic type, the false result can be decided by walking the target's properties in order and comparing the source property types directly, without `checkTypeRelatedTo`. the conditions that keep it identical to the relater: no shared generic alias between source and target (alias variance), not a weak target, not a fresh object literal source, no private/protected members on the way, stop and fall back at the first structured property type or if every property relates (signatures and index signatures follow)

measured in a Rust port of the checker that has to keep the relation cache and the instantiation count identical (so it still performs every property lookup the relater would, and records the same cache entries): about -11% of the N x M term on a synthetic union (500-1000 members, one `Extract` per key; quadratic before and after), neutral on vscode, webpack, mui-docs and xstate, -0.5% instructions on a 38k-file program at 4 checkers. a timing experiment that skips the lookups too (not cache-identical, so not shipped there) took about -20% of the N x M term and -1.1% instructions single threaded on the 38k-file program; that is roughly what a version in the Go checker could get, since it doesn't need to keep relation cache contents identical

the larger win would be asymptotic: re-instantiating a union of deferred conditional types of one root as one distribution, with a key-property index to evaluate only the matching constituents. that changes which `getConditionalTypeInstantiation` cache entries exist and the instantiation count per constituent (and so where the 5M instantiation limit trips), so it needs a decision on whether those may change

no test changes expected; the conformance suite has few of these shapes (the port's cross-check saw dozens of decisions there, hundreds of thousands on the 38k-file program, all agreeing with the relater)
